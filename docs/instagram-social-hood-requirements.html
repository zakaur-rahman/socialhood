Instagram requirements for Social Hood

What the Instagram Platform allows Social Hood to build, what it requires, where its limits are, and exactly how Social Hood should integrate with it. Every fact is labelled and traceable to Meta's official documentation.

1Executive summary

Social Hood connects Instagram professional accounts (Business or Creator) through Instagram API with Instagram Login, which needs no Facebook Page. Verified [I1] That setup covers everything in Social Hood's first release: direct messages, comments, comment-to-DM private replies, publishing and insights.

Instagram provides

  • Real-time webhooks for DMs, echoes of messages the business sends, reactions, read receipts and comments (including @mentions in comments). Verified [I3]
  • Sending DMs (text, images, audio, video, PDF, quick replies, templates) within 24 hours of the customer's last message; up to 7 days with the approved Human Agent feature. Verified [I5][I7]
  • Public replies, hiding, deleting and turning off comments, and one private DM per comment within 7 days. Verified [I4][I6]
  • Publishing images, carousels (2–10 items), Reels and Stories. Verified [I9]
  • Post and account insights: views, reach, likes, comments, shares, saves, interactions, follows. Verified [I10][I11]

Instagram does not provide (to this setup)

  • Liking posts or comments: available since April 2026 only through the Facebook-Login API (instagram_manage_engagement). Verified [I2]
  • Full DM history: the Conversations API returns only the 20 most recent messages of a thread. Verified [I8]
  • Metric webhooks: every count must be polled; story_insights is Facebook-Login only. Verified [I3]
  • Webhooks for comment edits or deletes: none documented. Verified [I4]
  • Hashtag search, product tagging, ads: Facebook-Login only. Verified [I1]
  • Unlimited automation: private replies are capped at 750 per hour per account. Verified [I12]
What gates launchReceiving webhooks for accounts Social Hood does not own requires the Meta app to be Live, Advanced Access through App Review (with a screencast per permission and at least one successful API call), and Business Verification. As a service for other businesses, Social Hood is a Tech Provider, which adds access verification. Verified [I1][I3][I13] Plan these weeks ahead of launch; development can proceed with test accounts that have a role on the app.

2Architecture

flowchart TD
  IGU["Instagram (customers comment, message, react)"] --> MW["Meta Webhooks (batches up to 1,000 updates, retries)"]
  MW --> GW["Social Hood webhook gateway: verify signature on raw bytes, split, store once, 200 in under 500 ms"]
  GW --> EQ["Event queue (job table in PostgreSQL)"]
  EQ --> WK["Workers: interactive lane (DMs, sends) · bulk lane (comments, sync, metrics)"]
  POLL["Scheduled polling: media, comments reconciliation, insights, token refresh"] --> WK
  WK --> DB["PostgreSQL: accounts, contacts, conversations, messages, comments, media"]
  WK --> AS["Analytics tables: post snapshots, daily account metrics"]
  WK --> AI["AI processing: classify, retrieve, draft, policy"]
  AI --> DB
  WK --> API["Instagram Graph API (graph.instagram.com/v25.0): send, reply, publish, read"]
  DB --> DASH["Social Hood dashboard (live via event stream)"]
  AS --> DASH

Inbound data arrives by webhook where Instagram offers one (messages, comments) and by polling where it does not (metrics, media list, token refresh, gap reconciliation). Outbound actions (sends, replies, publishing) always go through workers with per-account rate limiting. Recommendation

5Webhook architecture

Delivery facts

FactSource
Verification: GET with hub.mode=subscribe, hub.challenge, hub.verify_token; echo the challenge. Valid TLS; "Self-signed certificates are not supported."Verified [I3]
Signature: X-Hub-Signature-256: sha256=<hex>, SHA256 HMAC of the payload with the app secret. Instagram Login has both a Meta app secret and an Instagram app secret; which one signs is unclear.Verified / Unknown [I3]
Batches of up to 1,000 updates, not guaranteed; time is when the notification was sent, not when the event happened.Verified [I3][I18]
Retries "immediately, then … over the next 36 hours"; duplicates must be handled; no historical query.Verified [I3]
Messaging webhooks: respond "within 5 or less seconds"; alert after 15 minutes of failures; after 1 hour "Webhooks Disabled" and the app is unsubscribed from the account; order not guaranteed during failures (use timestamp).Verified for Messenger and Instagram conversations [I17]; IG Login applicability Unknown
Optional mTLS with Meta's CA (meta-outbound-api-ca-2025-12.pem, CN client.webhooks.fbclientcerts.com).Verified [I3]

Dedupe keys

  • Message, echo: ig:msg:{mid}. Reaction: ig:react:{mid}:{sender}:{action}:{timestamp}. Read: ig:seen:{recipient}:{sender}:{mid}. Edit: ig:edit:{mid}:{num_edit}.
  • Comment: ig:comment:{comment_id}. Keep keys 30 days (longer than the 36-hour retry window). Recommendation

10Implementation checklist

Meta setup

  • ☐ Create a Business-type Meta app; add "Instagram API setup with Instagram login".
  • ☐ Record the Instagram app id and secret (not the Meta app id/secret) in the secret store.
  • ☐ Configure the redirect URI, deauthorize URL and data-deletion URL in Business login settings.
  • ☐ Configure the webhook callback URL and verify token; subscribe the app to comments, messages, message_reactions, messaging_seen, message_edit.
  • ☐ Complete Business Verification; start Tech Provider onboarding and access verification.
  • ☐ Make one successful call per permission; record screencasts; submit App Review for Advanced Access to basic, comments, messages, content publish (and insights, Human Agent).
  • ☐ Switch the app to Live.

Verification spike (one day, test account)

  • ☐ Which secret signs X-Hub-Signature-256.
  • ☐ Comment payload shape (value.id vs comment_id, changes[], parent_id) and whether replies and our own API replies trigger webhooks.
  • ☐ Accepted subscribed_fields names; whether echoes need message_echoes.
  • ☐ Whether private replies need manage_messages; error on a second private reply and after 7 days.
  • ☐ IGSID equality between comment from.id, DM sender and private-reply recipient_id.
  • ☐ Actual content_publishing_limit.quota_total; feed video vs Reels.
  • ☐ Conversations API behaviour for pre-connection history.
  • ☐ Whether "Allow access to messages" is required; whether Creator accounts need a Conversations call first.
  • ☐ Presence of X-Business-Use-Case-Usage on graph.instagram.com.
  • ☐ Deauthorize and data-deletion payloads and signing secret.
  • ☐ Human Agent request syntax (after approval).

Build

  • ☐ OAuth connect with state, long-lived exchange, /me check, encrypted storage, webhook subscription, media sync.
  • ☐ Webhook gateway: raw-body HMAC, split, webhook_events with unique dedupe keys, enqueue, 200; 5 MB body limit.
  • ☐ Message handler: contacts, conversations, messages (unique mid), echoes as outbound, reactions, reads, edits; story-mention media not stored.
  • ☐ Comment handler: skip own comments; unique comment id; automation trigger; analysis marking.
  • ☐ Per-account token buckets: Send 100/s and 10/s, private replies 750/h, Conversations 2/s.
  • ☐ Send pipeline with 24 h window, Human Agent flag, 1,000-byte text limit, delivery_unknown handling.
  • ☐ Private-reply queue with ETA, surge modes, 7-day expiry.
  • ☐ Reconciliation job (comments_count compare); daily re-subscribe; webhook error alerting.
  • ☐ Token refresh job and reconnect flow.
  • ☐ Publishing: quota check, containers, 60 s then 5 min polling, error mapping.
  • ☐ Metrics: snapshot schedule (fields early, insights later), daily account metrics.
  • ☐ Deauthorize and data-deletion endpoints with status page.
  • ☐ Contract tests with recorded real payloads for every webhook and API shape.
